# Context-Aware Prompt Steering (CAPS)
## Improving Structural Conformance in LLM-Generated Code

This repository contains the full experiment infrastructure for the research paper:

> **Context-Aware Prompt Steering for Improving Structural Conformance in LLM-Generated Code**

The pipeline supports a controlled paired experiment comparing a Baseline prompt against a CAPS-steered prompt across 10 software design-pattern tasks. All LLM generation is manual; this tooling manages prompts, raw output storage, evaluation, aggregation, and figure generation.

## Formal Experiment Workflow

The design is: **10 tasks × 2 conditions × 5 runs = 100 generations per model.**

Both conditions receive the same automatically generated partial class
skeleton. Only CAPS receives the generated structural contract; the baseline
does not receive the contract checklist. The Factory contracts require
`create_notification` and `create_document` to be static methods.

### Step 1 — Generate prompts for a task/run

```bash
python collect_generation.py prompt \
    --model <model_id> \
    --task <task_id> \
    --run <N>
```

Example:
```bash
python collect_generation.py prompt \
    --model gpt-4o \
    --task observer_01 \
    --run 1
```

This saves separate `prompt.txt` files for both conditions to:
```
results/experiments/<model_id>/<task_id>/baseline_run_<NN>/prompt.txt
results/experiments/<model_id>/<task_id>/caps_run_<NN>/prompt.txt
```

Add `--show` to also print the prompt text to the terminal.

---

### Step 2 — Run the LLM (manually) & Save Response Safely

1. Open the LLM in a **fresh conversation**.
2. Copy the **baseline** prompt from `baseline_run_<NN>/prompt.txt`.
3. Paste it into the LLM and receive the response.
4. Save the **exact raw response** to a text file (e.g. `response.txt`).

> **CRITICAL FOR RESEARCH INTEGRITY & INDENTATION PRESERVATION:**
> - **How to Save:** Save the response directly using a text editor (e.g., VS Code or Notepad) with UTF-8 encoding.
> - **Avoid Shell Redirection / Terminal Stdin:** Do NOT use PowerShell redirection (`"..." | Set-Content` or `>` or terminal stdin paste in cmd/powershell), as shell line-discipline can strip leading indentation from `@decorator` and `def` statements.
> - **No Code Repair:** Do not repair, reformat, or modify the LLM response before saving. Raw output is preserved exactly.
> - **Markdown Fences:** Include the Markdown code fences (` ```python ... ``` `) if the model produced them. The pipeline handles fence extraction for normalization without modifying the code inside.

---

### Step 3 — Inspect, Record, and Evaluate

Optionally inspect the response file before recording:
```bash
python collect_generation.py check --file response.txt
```
This runs a non-destructive audit report (checking AST validity, Markdown fences, CRLF/LF line endings, and flagging suspicious column-0 line breaks if indentation was lost during copy/paste).

Record the response:
```bash
python collect_generation.py record \
    --model <model_id> \
    --task <task_id> \
    --condition <baseline|caps> \
    --run <N> \
    --file <path_to_response.txt>
```

Example — recording baseline for observer_01 run 1:
```bash
python collect_generation.py record \
    --model gpt-4o \
    --task observer_01 \
    --condition baseline \
    --run 1 \
    --file response.txt
```

This:
- Saves `raw_code.txt` (never modified)
- Runs structural (AST) + functional evaluation
- Saves `evaluation.json` and `metadata.json`

Repeat for the `caps` condition.

The `--model` value is retained in routing and metadata, and
`--model-version` is recorded only when supplied. No API is called by this
repository; generation remains a manual copy/paste workflow.

---

### Step 4 — Check status

```bash
python collect_generation.py status --model <model_id>
```

Shows a completion grid (✓ = complete, R = raw only, . = empty) for all 10 tasks × 2 conditions × 5 runs.

---

### Step 5 — Re-evaluate if needed

If you need to re-run evaluation on an already-recorded `raw_code.txt`:

```bash
python collect_generation.py evaluate \
    --model <model_id> \
    --task <task_id> \
    --condition <baseline|caps> \
    --run <N>
```

## Where to Save LLM Outputs

Each generation is stored in:

```
results/experiments/<model_id>/<task_id>/<condition>_run_<NN>/
```

| File | What it is |
|---|---|
| `prompt.txt` | Exact prompt given to the LLM (generated automatically) |
| `raw_code.txt` | Exact LLM response — never modified |
| `normalized_code.py` | Fence-stripped copy for execution (only if different from raw) |
| `evaluation.json` | Structural + functional evaluation results |
| `metadata.json` | Full experiment record |

**Never overwrite `raw_code.txt`** unless explicitly using `--force`.

## Research Integrity Guarantees

- Generated code is **never repaired** before evaluation.
- Raw LLM output is stored **exactly as received**.
- Markdown fence stripping is applied only to a **copy** for execution.
- Failed runs are **never silently discarded**.
- Pilot data is **explicitly excluded** from formal analysis.
- Timestamps are real; model versions are recorded as provided.
- All analysis is **fully reproducible** from raw `metadata.json` records.
